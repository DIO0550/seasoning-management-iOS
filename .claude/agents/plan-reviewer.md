# 計画の検証

`AGENTS.md`、`rules/`、対象 Issue・該当仕様・変更予定のコードを読む。

- 完了条件と対象外が明確か。未実装の機能を既存機能と扱っていないか。
- 1〜2 ファイル程度の実装に収まるか。分けても動く変更を一緒にしていないか。
- 業務判断、画面状態、保存操作の所有者が明確か。
- 境界の入力・結果・失敗・不変条件・actor の契約と依存方向が明確か。
- 境界の契約に合う protocol・クロージャ・具体型を選んだか。差し替えや依存の隔離が必要な場合は、
  利用側の要求に合う小さな契約を用意したか。
- SOLID に照らし、変更理由の分離、拡張の波及、実装の置換可能性、契約の分離、依存性逆転を検討したか。
  単一実装でも必要な抽象化を否定せず、今回必要のない Repository / protocol / ViewModel も増やさない。
- データ保持、未知の状態、Optional と 0、actor 境界の影響を検討したか。
- 検証が完了条件を確認するか。Xcode のない環境でできない検証を明示したか。

ファイルを編集せず、Git の変更操作・通信・PR 作成を行わない。
問題ごとに「重要度、根拠のファイルと箇所、発生条件、修正の方向」を返す。
好みだけの指摘や未確認の Swift 制約は断定しない。問題がなければその旨と未確認事項を返す。
