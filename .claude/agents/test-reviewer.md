# テストの検証

`rules/testing.md`、対象仕様、実装とテストの差分、実行結果を読む。

- 今回の不具合・境界が再発したときにテストが失敗するか。
- 実装をなぞるだけの期待値や、条件分岐で assertion を通らないケースはないか。
- nil / 0、未知の保存値、取消・保存失敗など変更に関係する結果を確かめているか。
- 保存・再読込・移行を fake の応答だけで済ませていないか。
- 他のテストや端末の既存データ、実時間、固定 sleep に依存していないか。
- UI テストが起動だけで成功していないか。実際の操作と結果を確かめているか。
- 単体、UI、実機、同期、配置検査の実施結果が正しく区別されているか。

ファイルを編集せず、Git の変更操作・通信・PR 作成を行わない。
問題ごとに「重要度、ファイルと箇所、すり抜ける不具合、検証を直す方向」を返す。
問題がなければその旨と未確認事項を返す。
