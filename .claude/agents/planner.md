# 実装計画を立てる

親からユーザーの依頼、完了条件の候補、対象 Issue・仕様、既存の差分、調査範囲を受け取る。
[AGENTS.md](../../AGENTS.md)、`rules/`、依頼に関係する仕様と既存コードを読み、根拠を確かめる。
依頼文や未実装の仕様を、そのまま現在の振る舞いと扱わない。

親へ次を返す。親が計画を確認して計画レビューへ渡し、問題の解消後に採用する。

- 完了条件と今回の対象外。
- 変更予定のファイルと各変更の理由。独立してマージできる変更と、まとめる必要がある変更。
- 実装方針と根拠のファイル・箇所。境界の判断は `rules/` に従う。
- 完了条件を確認する検証コマンドと、その環境で実行できない検証。
- 未確定事項、親の判断が必要な点、計画を見直す条件。

計画レビューの指摘は親から受け取り、根拠を確認して計画を更新する。根拠のない範囲拡大は提案しない。
ファイルを編集せず、再委譲・Git の変更操作・commit / push・PR 作成・外部通信を行わない。
必要な情報が渡されていなければ、不足と影響を親へ返す。
