# マージ後の結果を記録する

1. 対象 PR がマージ済みであることを確認する。記録だけの PR は対象外とする。
2. PR の差分・関連 Issue・CI の実行履歴と失敗・レビューを収集する。
   GitHub の全体コメント、レビュー本文、行コメントの 3 種類をすべて確認する。
   このセッションでのユーザーの訂正も人の指摘として記録する。
3. 内部レビュー、手戻り、hook の実行は確認できるログやセッション履歴から取る。
   別セッションの履歴など取得できない材料は「不明」とする。
   指摘がないことと、取得できないことを区別する。
4. [記録テンプレート](../../../harness/records/template.md) に従い、
   `harness/records/pr-<番号>.md` を作る。
   指摘ごとに 1 ブロックで分類と出どころを記し、指摘 0 件でも記録する。
   出どころの `internal` と、人・bot・CI を混ぜない。
5. [記録の規則](../../../harness/records/README.md) を確認し、
   最新の既定ブランチから記録用ブランチを作る。
   push 前検査を実行し、その 1 ファイルだけの PR を出す。

すでに記録があれば重複作成や上書きをせず、既存の記録を報告する。
過去の記録を書き換えない。新しい検証を始めて実装を蒸し返さない。
この依頼では `rules/`・hook・スキル・判例を変更しない。
規約の改善が必要でも、この記録の PR に同梱しない。
