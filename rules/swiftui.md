# SwiftUI の状態と画面

- `body` は表示の組み立てに集中させる。保存・OCR・重い計算を描画の評価中に実行しない。
- View 自身が所有する一時状態は `@State`、親の値を編集する受け口は `@Binding` を基本にする。
  複数画面が共有する状態だけ共有化し、すべての画面へ ViewModel / singleton を作らない。
- 派生値は元の状態から計算する。相互に矛盾する複数の Bool は必要なら `enum` にまとめる。
- 入力中の draft と保存済みモデルを区別し、キャンセル・保存失敗で保存済みデータを壊さない。
- 意味のある表示部分を子 View へ分ける。何でも `AnyView` に包んで型検査を避けない。
- ViewBuilder の `if/else` / `switch` は表示分岐に使ってよい。
  通常の関数の早期 return 規則を `body` の組み立てへ機械的に適用しない。
- 非同期処理の開始場所・取消・重複実行時の扱いを決め、UI を更新する実行場所を確認する。
- 一覧の識別子には安定した ID を使う。配列の位置や描画ごとの新しい UUID を代用しない。
- UI 変更は空状態・入力エラー・保存失敗・戻る操作を確認し、Dynamic Type と操作可能なサイズを保つ。
  HTML モックや `#Preview` の確認だけで iOS の実行確認を済ませない。
