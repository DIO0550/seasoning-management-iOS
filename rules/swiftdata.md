# SwiftData と保存境界

- 永続化の属性と業務の必須条件を区別する。スキーマの Optional / デフォルト値だけで入力を有効扱いしない。
- 保存前の整合性検証と状態更新の入口を決め、複数の画面に同じ保存判断を散らさない。
  `@Model` の属性定義だけを理由に別のドメイン層・Repository・protocol を一式追加しない。
- `ModelContext` の寿命と所有者を明示する。insert / delete / save の失敗を握りつぶさず、再試行できる入力を保つ。
- 名前や保存順を ID の代わりにしない。同名の商品を仕様の根拠なく自動統合しない。
- `nil` と 0、表示名と保存値、商品と個体を区別する。価格・栄養値の単位と精度は該当仕様に合わせる。
- enum の保存値に未知の値が来た場合を扱い、既知の状態へ暗黙に補完しない。
- モデル変更では既存ストアの読み取り、リレーション、削除規則、移行の必要性を確認する。
  開発時のストア削除で通ったことをデータ移行の成功と扱わない。
- CloudKit を見据えたスキーマでは一意制約・リレーション・デフォルト値の互換性を確認する。
  entitlement があるだけで同期済みと扱わず、ローカル保存と複数端末の同期を別に検証する。
- 旧 Core Data のモデルは移行資料として読む。旧ストアのコピー・削除・更新は復旧方法と移行検証を伴わせる。
