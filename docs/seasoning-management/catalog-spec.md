# 商品カタログ仕様（iOS画面）

> [概要](./index.md) / [データモデル](./data-model-spec.md)

## 役割

商品情報を1件登録すれば、同じ種類の複数本に名前・種類・画像・価格・栄養素を共通で使える。商品は個体の数や期限を保持しない。

## 画面と操作

| 画面 | 表示 | 操作 |
|:--|:--|:--|
| 商品一覧・選択 | 種類別の商品名、画像、紐づく未開封・使用中の本数 | 商品を選んで個体登録へ、商品登録へ、編集へ |
| 商品登録・編集 | 基本情報、価格、栄養素、画像 | 入力、画像選択・削除、商品名の読み取り、保存、キャンセル |
| 商品詳細 | 登録内容と個体の一覧への導線 | 編集、削除を開始 |

商品登録後は登録した商品を選択状態として個体の追加に進める。キャンセル時は新規商品を保存しない。画像がない場合は代替表示を使う。写真は端末の写真ライブラリから選び、選択しないこともできる。

商品名の読み取りではパッケージを撮影するか写真を選び、[OCR仕様](./ocr-spec.md)に従って候補を表示する。選んだ候補だけを名前欄へ反映し、利用者が編集してから保存する。認識用画像を商品画像へ自動設定しない。

## 入力項目

| 項目 | 必須 | 保存内容・入力規則 |
|:--|:--|:--|
| 名前 | はい | 前後の空白を除いた空文字を拒否する。 |
| 種類 | はい | 自由入力。下記の共通入力規則に従う。 |
| 画像 | いいえ | 選択した写真。編集時は差し替え・削除できる。 |
| 価格 | いいえ | 0以上の整数の円。未入力は `0` と区別して保存する。 |
| カロリー、タンパク質、脂質、糖質、炭水化物 | いいえ | 単位・基準量・小数精度・未設定の扱いは下記の共通入力規則に従う。 |
| 栄養素の基準量・基準単位 | 条件付き | 栄養素を1項目でも入力した場合に必須。全項目に同じ基準を用いる。 |

数値の不正入力は保存せず、該当欄に理由を示す。入力途中の値は保存成功まで保持する。重複した名前の商品を機械的に統合しない。同名でも異なる商品を登録できる。

## 種類・栄養素の共通入力規則（#14）

Issue #14で種類の入力方式と栄養素の単位・基準量・精度を以下のとおり具体化する。概要の旧レビュー一覧に残る未決定記述より、この規則を優先する。種類の表示順・検索は今回の決定対象に含めない。

### 種類と空白

- 種類は必須の自由入力とする。前後の空白・改行を除き、空文字を拒否する。内部の表記は変更せず、表記ゆれや同名・同種類の商品を自動統合しない。
- この節の周辺空白除去には半角・全角スペース、タブ、改行、Unicodeの空白文字を含める。種類・基準単位の内部空白は保持し、数値内の空白は不正な書式として拒否する。

### 栄養素と基準

| 入力項目 | 単位 | 入力範囲・精度 |
|:--|:--|:--|
| カロリー | kcal | 0以上、小数点以下2桁まで。任意 |
| タンパク質・脂質・糖質・炭水化物 | g | 各項目とも0以上、小数点以下2桁まで。各任意 |
| 基準量 | 基準単位と組み合わせる | 0より大きい値、小数点以下2桁まで。栄養素があれば必須 |
| 基準単位 | 自由入力（例: `g`、`mL`、`食`、`個`、`杯（大さじ）`） | 前後の空白・改行を除いた非空文字列。栄養素があれば必須 |

- 5つの栄養素はそれぞれ独立した任意入力とする。空欄は未設定（`nil`）、明示した `0` は数値の0として保存する。編集で値を消した場合も `nil` に戻す。糖質と炭水化物など、他の項目から計算・補完しない。
- 周辺空白を除いた栄養素の入力文字列が1項目でも非空なら、全栄養素に共通の基準量・基準単位を必須にする。`0` も入力済みに含める。入力済みかどうかを数値変換の成否で判定せず、`abc` や `NaN` は検証エラーとし、未設定へ置き換えない。
- 栄養素が全て空欄なら、5項目・基準量・基準単位を全て `nil` にする。基準だけ入力していても保存されないことをフォームに示す。最後の栄養素を消した場合も同じ扱いとする。新規フォームは全て空欄で開始し、100gを暗黙に設定しない。
- パッケージの基準をそのまま入力する。例: `100`＋`g`、`15`＋`mL`、`1`＋`食`、`1`＋`個`、`1`＋`杯（大さじ）`。1食分の重量や大さじの容量を推測せず、100gへの換算やgとmLの変換を行わない。基準を確認できない場合は栄養素を未設定にして商品を保存できる。
- 入力欄には栄養素の単位を常時表示し、詳細には基準量・基準単位と「あたり」を併記する。未設定は「未設定」、0は単位付きの `0` と表示する。再編集時の未設定欄は空欄とし、5項目をそれぞれ対応する欄へ復元する。
- 基準量・基準単位を編集しても、既存の栄養値を自動換算しない。全栄養素の基準が変わることをフォームに示し、全入力値を保存前に見直せるようにする。

### 数値書式と論理保存値

- 周辺空白を除去した数値は、半角数字の整数部と、任意の小数点 `.` ＋1〜2桁で入力する。符号・指数表記・桁区切り・単位混在・数値でない文字列・小数点のみ・末尾小数点・小数点以下3桁以上は拒否する。丸め・切り捨て・不正値の0への置換は行わない。
- 栄養素・基準量は正確な十進数として検証し、100倍した整数を各 `Int64?` の論理保存値とする（`0.01` → `1`、`12.34` → `1234`、`0` → `0`、空欄 → `nil`）。浮動小数点の近似値から丸めて保存しない。表示・再編集時は100分の1の値に戻し、不要な末尾の0は省略できる。
- 保存可能な栄養値は `0`〜`92233720368547758.07`、基準量は `0.01`〜`92233720368547758.07` とする。100倍した整数が `Int64` の範囲を超える値は拒否する。この上限は保存形式上の制限であり、栄養学上の妥当性を保証するものではない。
- 画面と保存直前で同じ検証を行う。不正入力時は該当欄に理由を示し、入力を保持して商品全体を保存しない。一部だけ保存しないという業務要件であり、具体的なトランザクション方式は指定しない。
- 価格にはこの小数規則を適用せず、従来どおり任意の0以上の整数の円とし、未設定と0を区別する。業務上の必須とSwiftData / CloudKitの永続化Optionalを混同せず、具体的な栄養値の配置と同期互換性は後続の検証で決める。
- 単位・基準が不明な旧 `SeasoningNutrients` の整数を、新しい100倍整数として転用・換算しない。旧 `Seasoning` にない栄養素・基準量・基準単位は `nil` とする。

## 入力仕様の確認例

名前など、例に記載していない必須項目は有効な値が入力済みとする。以下は画面・保存・再編集で共通の確認条件であり、実装済みの動作を示すものではない。

| 入力・操作 | 期待する結果 |
|:--|:--|
| 種類が `  しょうゆ  ` / 全角空白・タブ・改行のみ | 前者は `しょうゆ` で保存。後者は保存不可。内部表記は自動統合しない。 |
| 栄養素が全て空欄（基準だけ入力している場合を含む） | 栄養素5項目・基準量・基準単位は全て `nil`。基準だけでは保存しない旨をフォームに表示。 |
| 基準 `100`＋`g`、脂質 `0`、ほかは空欄 | 基準量は `10000`、脂質は `0`、ほかの栄養素は `nil`。脂質は `0 g` と表示。 |
| 基準 `15`＋`mL` / `1`＋`食` / `1`＋`個` / `1`＋`杯（大さじ）` | 基準量は順に `1500` / `100` / `100` / `100`。単位はそのまま保存し、重量・容量へ換算しない。 |
| 基準 `1`＋`食`、カロリー `12.34`、糖質 `0.01` | カロリーは `1234`、糖質は `1`。`1食あたり`、`12.34 kcal`、`0.01 g` と再表示。 |
| 栄養素あり、基準量が空欄・0・負数、または基準単位が空白のみ | 保存不可。該当欄に理由を表示し、入力を保持。明示した栄養値0にも同じ基準必須ルールを適用。 |
| 数値が `-1`、`+1`、`1.234`、`1e2`、`1,000`、`abc`、`NaN`、`1 g`、`.`、`1.`、`1 2` | 保存不可。3桁目が0の `1.230` も拒否。未設定や0へ置換せず、丸め・一部保存もしない。 |
| 栄養値または基準量が `92233720368547758.07` / `92233720368547758.08` | 前者の100倍整数は `9223372036854775807` で保存可能。後者は範囲外で保存不可。 |
| 保存済みの最後の栄養素を消して保存・再表示 | 栄養素・基準量・基準単位は全て `nil`。再編集時は空欄。 |
| 脂質 `1.23`、糖質 `4.56` を保存して再編集 | 脂質は `1.23`、糖質は `4.56` と各欄へ復元し、取り違えない。 |
| 基準 `100`＋`g` を `15`＋`mL` に変更 | 基準変更の影響を表示し、栄養値は自動換算せず、見直した入力を保存。 |
| 価格が空欄 / `0` / `1.23` | 順に未設定 / 0円 / 保存不可。栄養素用の小数規則を価格へ広げない。 |
| 単位・基準不明の旧栄養整数を参照 | 新しい100倍整数として読み替え・換算しない。旧 `Seasoning` にない栄養素・基準は未設定。 |

## 商品削除

- 未開封・使用中・使い切り履歴の**いずれか**の個体が紐づく商品は削除不可とする。件数と理由を表示する。
- 紐づく個体が0件なら、確認を経て商品情報と画像を削除する。
- 削除は同期対象とし、別端末で削除済み商品が復活しないようにする。

## エラーとアクセシビリティ

- 保存・画像読み込み・同期で失敗したら理由と再試行手段を示す。保存に失敗した入力内容を消さない。
- VoiceOver が各項目名と値、必須かどうか、エラーを読めるようにする。文字サイズ変更で主要操作が隠れないようにする。
- 同期が保留中でもローカル保存に成功した場合は保存成功として扱い、同期状態は別に表示する。

## 既存コードとの関係

旧 UIKit / Core Data アプリの `Seasoning` は名前・種類・画像を個体と同じレコードに持つ。さらに古い試作の `SeasoningData` は価格と栄養素を含む商品に近い。旧登録画面は未入力や不正な数値を `0` にしていたが、この仕様では区別する。移行は[同期・移行仕様](./sync-migration-spec.md)を参照。
